2. **`eff_deg ≥ 50%` 门槛（OP-6）：六个任务全部 100% 通过** —— graph-eligible 的四个 landscape 的邻域可见性都没有边界效应问题。
3. **Phillips2023 的 MA90 是唯一"完全干净"的任务**：无下限 → 0 删失；present 65,530、informative 65,530（**100% 转化**）。

### ⚠️ 过程记录：我自己的一次错误（值得留档）

第一次计算 CR9114 时，我用了 `genotype` 列作为 measurement key，而图节点用 `pos1..pos16` 拼接。**该 CSV 的 `genotype` 列被 pandas 读成整数，前导零被剥掉**（如 `1111110011011` 只有 13 位 vs 正确的 16 位），导致**约一半 key 恰好撞对**，输出 `eff_deg` 均值**恰好 8.0**、`eff_deg=16` 占比 **0.00%**。

- **表象是"合理"的数字，实际全错。** 只有"均值恰好等于理论最大的一半"这个可疑签名（外加 `present` 计数正常）暴露了问题。
- 修正后（统一使用 pos 拼接字符串）与我的**三处独立测量精确吻合**：`censored` = **436 / 58,127 / 65,243**，`present` = **65,094 / 65,535 / 65,534**。
- **教训（写入规程）**：① 凡涉及 genotype 字符串的表，**读取时一律 `dtype=str`**；② 图节点 key 与 measurement key **必须由同一构造路径产生**；③ 出现"某个统计量恰好等于理论值的一半/整数"时，**先怀疑 key 未对齐**。

## 1d｜对账结论：两个真实缺陷 + 我自己的两次误判

### ✅ 先说通过的部分

用**正确的组键** `(dataset | task | condition | genotype)` 复核：

| 检查 | 结果 |
|---|---|
| 组级字段组内恒定性 | `measurement_state` / `informative` / `value_sem` / `value_sd` / `floor` / `n_observed` **全部 0 违规 / 1,232,865 组** |
| 每组行数分布 | `{1: 9,244, 2: 257,641, 3: 965,980}`（与缺失重复账目自洽） |
| 结构性计数（present / censored / missing） | **与我的独立测量精确一致**（见 §1c 表） |

> ⚠️ **我的第 1 次误判**：我最初按 `genotype_id` **单独**分组检查恒定性，把 14 个条件混在一起，误报"TEM-1 有 4,721 个组 `informative` 不恒定"。**正确组键下 0 违规。这是我的错，不是交付方的。**

### 🔴 缺陷 A（真实）：CR9114 的 `genotype_id` **丢失前导零 → key 非规范**

| 证据 | 值 |
|---|---|
| `genotype_id` 唯一值长度分布 | `{1:2, 2:2, 3:4, 4:8, …, 15:16384, 16:32768}` ← **正是指数型"剥前导零"签名** |
| 命中「规范 16 位串」 | **32,768 / 65,536（仅 50%）** |
| 命中「去前导零形式」 | **65,536 / 65,536（100%）** |
| 成因 | 读 `cr9114.csv` 时未指定 `dtype=str` → `genotype` 列被解析为整数 |

**后果**：该 key **无法与图节点 join**（`eov/landscape.py` 的节点 id 由**所有位点等位拼接**产生，CR9114 的规范 key 必须来自 `pos1..pos16`）。任何按 genotype 的 join 会**静默失配**。

> ⚠️ **我的第 2 次误判（同源）**：我第一次算 CR9114 有效 degree 时也用了非规范 key，得到"均值恰好 8.0、eff_deg=16 占比 0.00%"这种**看似合理但全错**的数字。**同一个坑，两个人都踩了。**
> → **规程增补**：① genotype 字符串一律 `dtype=str` 读；② 图节点 key 与 measurement key 必须由**同一构造路径**产生；③ 出现"统计量恰好等于理论值一半/整数"时**先怀疑 key 未对齐**。

### 🔴 缺陷 B（真实，更隐蔽）：`informative` 用**第一个重复值**作组代表值 → **依赖行序**

| 任务 | first-rep | mean | median | **交付** |
|---|---|---|---|---|
| CR9114 h1 | **62,916** | 62,817 | 62,762 | **62,916** |
| CR9114 h3 | **6,506** | 6,475 | 6,344 | **6,506** |
| Phillips2023 SI06 | **28,064** | 28,507 | 28,507 | **28,064** |

三处都**精确命中 "first replicate"** 规则。

**为什么这是缺陷（不是口味问题）**：

1. **它依赖输入行序** —— 文件换个排序，`informative` 就变（SI06 相差 **443**，1.6%）。**这是可复现性缺陷：不报错，只静默漂移。**
2. **schema v1.2 没有"组代表值"这一列**，而 CL-9 的 `informative = (state==measured_exact) ∧ (value > floor + 2·SEM) ∧ …` 中的 `value` 语义上必须是**组级代表值**。AMENDMENT-009 §3.2 原文是"组级值由剩余 N 个有效重复**导出**"，**不是**"取第一个"。
3. **TEM-1 作者自己的约定是 `median`**：`DATA_README.md` 写明 `Fitness : Median AUC value (from long format files)`，且 `Epistasis_Combined.parquet.Fitness = median AUC`。

**修法（已发给交付方；将构成 schema v1.3 的 metadata 增量）**：
- 主表**新增 `value_group`**（组代表值），**冻结规则 `value_group = median(该组所有有效重复)`**；
- `informative` **一律由 `value_group` 计算**，不得再用单个重复值；
- 增补自检：`informative` 在正确组键下必须组内恒定，并贴出真实输出。

### 本轮结论

> **M2.1–M2.3 的 materialization 尚未通过验收。** `present` / `censored` / `missing` 的**结构性口径已验证可用**；但 **(a) CR9114 的 genotype key 非规范**、**(b) `informative` 依赖行序**，两项都必须修好才能进入 M2.4 的最终审计表。
> **在返工完成前，本文件不采纳任何 `informative` 计数，也不采纳 CR9114 的任何按-key 结果。**

## 3｜🔴 缺失重复的**结构**（不是随机缺失）

### 3.1 逐药物内部：**全部浓度共享同一批缺失基因型**

| 药物 | 各浓度的两重复基因型集合是否相同？ |
|---|---|
| Ampicillin | ✅ **完全相同**（6 个浓度同一批 46 个） |
| Aztreonam | ✅ **完全相同**（8 个浓度同一批 62 个） |

→ **与"生长差 → 测不到"的逐条件机制不符**；更像**测序批次 / 条码层面的技术假象**。

### 3.2 跨药物：**几乎不重叠**

| 项 | 值 |
|---|---|
| AMP 781 两重复基因型 | **46** |
| AZT 36 两重复基因型 | **62** |
| **交集** | **5** |
| 仅 AMP / 仅 AZT | 41 / 57 |
| **并集** | **103** |

→ AMP 与 AZT 的样本来自**不同测序批次**，缺失集合几乎不相交 —— 进一步支持"**批次级技术假象**"而非基因型内在属性。

### 3.3 ⚠️ 但缺失**偏向高突变负载**（潜在偏倚，必须记录）

| 分布 | 突变数 5 | 6 | 7 | 8 | 9 | 10 | 11 | 12 |
|---|---|---|---|---|---|---|---|---|
| **受影响基因型**（n = 103） | 2 | 6 | 19 | 23 | **29** | 16 | 6 | 2 |
| 全体基因型（n = 55,294） | 5,580 | 9,558 | **12,132** | 11,420 | 7,882 | 3,877 | 1,290 | 260 |

- 受影响基因型的**突变数均值 ≈ 8.49**；全体 ≈ **7.25**。
- 全体众数在 **7**；受影响集合众数在 **9**。
- → **高突变负载（因而更稀有）的变体更容易出现重复丢失**（条码数目少 → 测序深度不足）。

**含义（冻结）**：
1. 该缺失是**结构化（structured）而非随机**，须在 `DATA_AUDIT` 与后续分析中显式声明为**潜在偏倚**。
2. 规模很小（**46 / 55,294 = 0.083%** 的 AMP 组、**62 / 55,294 = 0.112%** 的 AZT 组），且**集中于高突变负载区**。
3. 按 AMENDMENT-009 §3.2：这些组记为 `n_expected=3, n_observed=2, n_missing=1`，**不填补、不判 censored、不虚构 SEM**；组级量由剩余 2 个重复导出。
4. **对 `degree_effective` 的影响**：受影响的 103 个基因型在**每个条件**上都会少 1 个可用邻居 → 其 eff_deg 上限为 17。**规模不足以改变 §2 的整体图景**。

## 4｜`task_panel` 的输出范围（硬防守生效）

按 AMENDMENT-009 §5 与 `graph_eligible()` 的代码级防守：

| 类别 | 允许输出 | 禁止输出 |

| `strict_multi_task` / `single_task_control`（TEM-1 / Phillips2023 / CR9114） | `degree_topology`、`degree_effective` | — |

已在 M2.0 验收中独立确认：`graph_eligible('task_panel', complete_product=True, observed==theoretical)` **恒为 `False`**；`allowed_qc_fields()` 使非 graph-eligible 者**取不到 degree 字段**。
