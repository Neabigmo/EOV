# Reproducibility

## What runs with no downloads

```bash
pip install -r requirements.txt
pytest tests                                   # 66 passed, 20 skipped
python scripts/verify_release.py               # privacy / size / structure
python scripts/reproduce_phase1.py --stage m7b # full M7-B gate
```

The 20 skips are the tests that need third-party data; they are skipped by
`tests/conftest.py` rather than deleted, so the identical command runs the full
suite once data is present.

**Verifiers** (each re-derives a headline number by an independent code path and
then checks the report text against the computed values):

| verifier | covers | checks |
|---|---|---|
| `eov/m6_verify_result.py` | M6 primary statistic, CI, per-pair values, permutation null | 85 |
| `eov/m7_verify.py` | M7 curve, single-draw quantiles, tertiles | 67 |
| `eov/m7b_verify.py` | M7-B `S_0` recomputation **and each of the three verdict conditions** | 65 |
| `eov/m6_verify_report.py` | M4 report numerics | 752 |

## What needs third-party data

```bash
python scripts/fetch_public_data.py --dataset wu2020     # 174 KB, CC-BY-4.0
python scripts/reproduce_phase1.py --stage m6            # ~11 s
```

`m7` additionally needs the M4 search matrices, which are regenerated by `m4`
(long-running). `m5` and `m4` need TEM-1 and Phillips2023.

Nothing silently falls back to a developer path: every stage reports exactly
which file is missing and which command fetches it.

## Determinism

* Seeds are frozen and listed in `configs/phase1_defaults.yaml`.
* The M6 search simulation was re-run from scratch and produced a
  **bit-identical** `R` array (`max|diff| = 0.0`) over 20,736 searches.
* M7-B, re-run inside this release tree, reproduced
  `ρ_zero = +0.3527`, CI `[−0.1520, +0.6747]`, `p = 0.01600`, verdict `NO-GO`.

## Preregistration and the audit chain

* `prereg/PHASE1_PROTOCOL.md` and `prereg/PHASE1_DECISION.md` — the frozen design.
* `prereg/amendments/AMENDMENT-001 … 022` — every design change, in order, each
  written **before** the analysis it governs.
* `data_registry/FREEZE_LEDGER.md` — append-only: per batch, the files added and
  their SHA-256.
* `data_registry/M4_LEAKAGE_AUDIT.md` — independent leakage audit.
* Self-reported errors are kept on purpose: `AMENDMENT-019` (a degenerate-cell
  rule frozen before any correlation was computed), `AMENDMENT-020` §3 (a
  pre-registered statistic that turned out not to be the decision-relevant one),
  `AMENDMENT-021` §3 (a verdict rule that was under-implemented and corrected).

## Two document classes — do not confuse them

1. **Frozen documents and frozen tests.** `prereg/M1_SCHEMA_SPEC.md` and the
   files under `tests/` are reproduced **verbatim**, because their SHA-256 hashes
   are asserted by tests or recorded in the freeze ledger. Two historical
   machine paths survive inside `tests/` for this reason; they are interpreter
   paths with no username, credential or email, and the trade-off is deliberate.
2. **Everything else.** Machine-specific paths in prose were replaced with
   `<PROJECT_ROOT>` / `<PYTHON>` in this release. See
   `prereg/amendments/AMENDMENT-022_release_redaction.md`.

## Repository layout

```
eov/            library + all M3–M7B analysis scripts (flat module namespace)
analyses/       milestone index for the analysis scripts (see its README)
tests/          pytest suite (conftest.py holds the data-presence guards)
configs/        frozen defaults + derived dataset manifest + M4 run configs
prereg/         protocol, decision, schema spec, amendments/
data_registry/  provenance ledger, freeze ledger, audit + milestone reports
results/tables/ the paper's result tables (small CSVs, regenerated by code)
data/manifests/ small checksum + run manifests
figures/        figure builders
scripts/        fetch / manifest / reproduce / verify entry points
docs/           this file and its siblings
```
